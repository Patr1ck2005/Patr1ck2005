# 从数值观测到可检查的结果

[English](tools-overview.md) · [完整作品目录](../README.zh-CN.md)

科研软件的价值，体现在另一个人能否理解输入、复现一个小结果，并看清哪些地方仍需要科学判断。这组工具围绕光子学、科学计算与可视化，尝试把这种具体的交接做好。

四个共享库各自承担一段职责：**campaign-data** 先检查文件与扫描覆盖；**eigenmode-analysis** 沿路径或参数图组织数值候选，保留缺失观测和分配诊断；**plot-foundation** 按明确的绘图描述渲染；**plot-workflows** 将分析输出接到可复用视图。组合示例自行生成数学数据，并对所宣称的结果进行检查。

![实际运行的合成工作流](https://raw.githubusercontent.com/Patr1ck2005/plot-workflows/main/docs/assets/showcase/hero.png)

这些曲线说明软件工作流，全部来自独立定义的合成量，不是某个光子器件的实验或仿真证据。追踪标签也需要物理解释：数值上连续的分支，不自动等同于唯一的物理模态身份。

其他项目分别探索标量光传播、参数化 GDS 版图、互动波场和游戏。各仓库明确区分可运行软件、原型、历史作品与保留上游归属的 fork；[完整目录](../README.zh-CN.md) 保留这些差异。

第一次使用可从[组合示例](https://github.com/Patr1ck2005/plot-workflows#run-the-end-to-end-example)开始，在新环境中使用其依赖文件：它选定互相兼容的稳定版本和 Matplotlib 3.10.9。独立的 eigenmode 0.3.1 分组路线应放在另一个环境。许可、来源和兼容范围以各仓库为准。

最有用的反馈是三个问题：示例能否运行？接下来想用于什么具体任务？缺少哪项能力才无法继续？一个可以分享的小输入和明确的期望输出，比泛泛的平台需求更容易带来合作。

私人科研编排、生产计算机队及当前实验专用模块继续保留内部。公开示例展示有限而明确的能力，不暴露进行中的研究。可以围绕数值光学、分析与科研工具讨论具体问题；这里没有承诺商业服务或生产支持。
